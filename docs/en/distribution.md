# Distribution

> Español: [docs/es/distribution.md](../es/distribution.md)

One binary, built once per target by [cargo-dist](https://axodotdev.github.io/cargo-dist/book/)
from [`dist-workspace.toml`](../../dist-workspace.toml). Every other channel repackages
those same files. There is no packaging code of our own.

## Channels

| Channel | How users get it | Built by | Status |
|---|---|---|---|
| GitHub Releases | archives + `sha256` + attestations | `release.yml` (generated by `dist generate`) | ✅ on every `v*` tag |
| Shell installer | `curl -LsSf https://github.com/exo273/any-mcp-codemode/releases/latest/download/any-mcp-codemode-installer.sh \| sh` | cargo-dist | ✅ |
| PowerShell installer | `irm https://github.com/exo273/any-mcp-codemode/releases/latest/download/any-mcp-codemode-installer.ps1 \| iex` | cargo-dist | ✅ |
| npm | `npx -y any-mcp-codemode serve` | `publish-npm.yml` via [trusted publishing](https://docs.npmjs.com/trusted-publishers) (OIDC, no token; provenance) | ✅ `0.1.0` (staged, approved with 2FA) |
| Docker | `docker run -i --rm -v ./cfg:/config:ro ghcr.io/exo273/any-mcp-codemode` | `docker.yml`, from the release's musl binaries | ✅ on every release |
| MCP Registry | `server.json` (OCI package) | `mcp-publisher` | ⏳ after the first image exists |
| Source | `cargo install --git https://github.com/exo273/any-mcp-codemode` | cargo | ✅ |

Targets: macOS arm64/x86_64, Windows x86_64/arm64 (MSVC, static CRT), Linux
x86_64/arm64 (**static musl**: one binary for every distro and for the `FROM scratch` image).

## Release procedure

1. Bump `version` in `Cargo.toml` and in `server.json` (both places), commit (`chore(release): vX.Y.Z`).
2. `git tag vX.Y.Z && git push --tags`.
3. `release.yml` builds and publishes the GitHub Release. Then `docker.yml` packages the image from the same binaries.

`dist plan` (also run on every PR) shows the artifacts without building anything.

## npm trusted publishing

`release.yml` calls `publish-npm.yml` (cargo-dist `publish-jobs = ["./publish-npm"]`), which
publishes with an OIDC token minted by GitHub Actions. There is no npm secret in the repo.
npm validates the **calling** workflow, so the trusted publisher on npmjs.com is configured as
`exo273` / `any-mcp-codemode` / `release.yml`. The job runs `npm stage publish` (always allowed for a trusted
publisher), so each version waits in **Staged Packages** until a maintainer approves it with 2FA
(`npm stage approve <id>` or npmjs.com). Releases stay green; the npm version just isn't public yet.

## Docker image

- `FROM scratch` + the static binary + CA certificates. About 19 MB, no shell, runs as UID 65532.
- `AMC_CONFIG=/config/any-mcp-codemode.json`: mount your config read-only at `/config`. The image runs as UID 65532, so the mounted directory and file must be world-readable (e.g. `chmod 755 dir && chmod 644 dir/any-mcp-codemode.json`); a `700` directory fails with `Permission denied`.
- `AMC_STORE=sqlite:/data/history.db?mode=rwc`: history goes in the `/data` volume. Use `postgres://…` for a shared store.
- Upstreams that need `npx`/`uvx` don't work inside `scratch`. Use `url` (streamable HTTP) upstreams in containers, or the native binary.

## Why npm is not in `server.json` yet

The MCP Registry verifies npm ownership through `mcpName` in `package.json`. The
`package.json` is generated by cargo-dist, which has no setting for extra fields.
Until it does (or we add a post-build step), the registry entry lists only the OCI image,
whose ownership is verified by the `io.modelcontextprotocol.server.name` label.

## Not yet (by design)

Homebrew (needs a tap repo), winget/scoop, `.mcpb`, PyPI. Each one is added only when
asked for, and as configuration over the same artifacts.
