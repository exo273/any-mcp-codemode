# Localization (i18n)

> Español: [docs/es/i18n.md](../es/i18n.md)

Launch languages: **English (`en`, source and fallback) and Spanish (`es`)**. Adding a
language means adding files. No code changes.

## 1. What is localized and what is not

| Surface | Localized? | Notes |
|---|---|---|
| CLI help, prompts, progress, success/error messages | ✅ | `any-mcp-codemode --help`, `any-mcp-codemode install`, `any-mcp-codemode import` |
| User-facing errors | ✅ message / ❌ code | Each error has a stable code (`CM0102`) plus a localized message. Users search by the code |
| Config produced by `any-mcp-codemode init` | ✅ comments | Keys stay English; generated comments use the user's language |
| Config JSON Schema (editor autocomplete/hover) | ✅ | `config.schema.json` (en) + `config.schema.es.json`; `$schema` picks one |
| Docs (`docs/<lang>/`) | ✅ | Same file tree for each language |
| Plugin/package metadata (npm, Claude Code `userConfig`, Hermes, MCPB) | ✅ where the format allows | Otherwise English with a link to `docs/es/` |
| Config **keys**, CLI **flags**, env var names | ❌ | Stable API: `limits.timeout_ms`, `--lang`, `AMC_LANG` |
| MCP protocol, tool names (`code`, `search`, `describe`), JSON fields | ❌ | Machine contract |
| Structured logs (`--log-format json`) | ❌ | English `message` + `code`; logs are for machines and support |
| Text the **model** sees (tool description, generated TS types) | ⚙️ separate setting | `model_locale`, default `en`: models perform best and use fewer tokens in English. Upstream tool descriptions are never translated |

## 2. Language resolution

The first match wins:

1. `--lang es` flag
2. `AMC_LANG` env var
3. `locale` in the config file
4. `LC_ALL` → `LC_MESSAGES` → `LANG` (POSIX, e.g. `es_CL.UTF-8`)
5. OS locale ([`sys-locale`](https://github.com/1Password/sys-locale): Windows, macOS, Linux, Android, iOS, WASM)
6. `en`

Negotiation follows BCP 47 with a fallback chain: `es-CL → es-419 → es → en`. A key
missing in `es` falls back to `en` at runtime, and CI fails on it (see §5).

`--lang` and `AMC_LANG` only change what the **user** sees. `model_locale`
controls what the **model** sees.

## 3. Engine: Project Fluent

[Project Fluent](https://projectfluent.org/) through [`fluent-rs`](https://github.com/projectfluent/fluent-rs)
(Apache-2.0/MIT, from Mozilla).

- It handles real plurals and selectors from CLDR (`{ $count -> [one] … *[other] … }`). Spanish and other languages need this, and `format!` does not.
- Named variables let translators reorder sentences freely.
- Weblate and Pontoon edit `.ftl` files directly, so the community can translate without touching Rust.
- `.ftl` files are compiled into the binary with `include_str!`. That keeps it a single binary with no runtime file I/O.

Rejected alternatives:

- [`rust-i18n`](https://github.com/longbridge/rust-i18n) (YAML, simpler): weak plural support.
- gettext: heavy C toolchain on Windows.

Layout:

```text
data/locales/en.ftl
data/locales/es.ftl
```

```ftl
# data/locales/en.ftl
CM0102 = Upstream server { $server } did not respond within { $seconds ->
    [one] { $seconds } second
   *[other] { $seconds } seconds
}.
    .hint = Raise limits.connect_timeout_ms or check the command: { $command }
```

```ftl
# data/locales/es.ftl
CM0102 = El servidor { $server } no respondió en { $seconds ->
    [one] { $seconds } segundo
   *[other] { $seconds } segundos
}.
    .hint = Sube limits.connect_timeout_ms o revisa el comando: { $command }
```

In code there are no literal user-facing strings. Everything goes through
`t!("CM0102", server = …, seconds = …)`, and a lint (§5) enforces this.

## 4. Configuration

```jsonc
{
  "$schema": "https://<docs-host>/schema/config.schema.es.json",
  "locale": "es",          // optional; otherwise auto-detected
  "model_locale": "en",    // language of the description/types sent to the model
  "servers": { /* … */ }
}
```

- The JSON Schema is generated from the Rust types (`schemars`). Descriptions come from `data/locales/<lang>/config.ftl` (keys `config-<path>`, phase 2), so code, docs and editor hover share one source.
- `any-mcp-codemode config explain limits.timeout_ms` prints the description, default and doc link in the user's language.
- Config validation errors show the JSON path (English, stable), a localized explanation and a link to `docs/<lang>/config.md#<anchor>`.

## 5. Quality gates (CI)

| Check | Fails when |
|---|---|
| `i18n-keys` | A key exists in `en` but not in `es` (or the reverse) |
| `i18n-vars` | A translation uses different `{ $variables }` than `en` |
| `i18n-unused` | A key in the `.ftl` files is never referenced in code |
| `no-literal-strings` | `println!`/`eprintln!`/error `Display` with a user-facing literal outside `t!` |
| `docs-parity` | A file exists in `docs/en/` with no counterpart in `docs/es/` |
| Snapshot tests | `any-mcp-codemode --help` for each locale (`insta`), so text changes are reviewed |
| Pseudo-locale `en-XA` | Optional: `[Ŧħïş ïş ŀőŋğëř]` to spot hardcoded or truncated strings |

## 6. Process

- A PR that adds or changes a key in `data/locales/en.ftl` changes `data/locales/es.ftl` too (the check enforces it). The commit uses scope `i18n` when the change is translation-only.
- Docs and translations go in the same commit as the feature, linked from `Docs:` (see [commits.md](commits.md)).
- New languages: copy `data/locales/en.ftl` to `data/locales/<lang>.ftl` and add one line to `LOCALES` in `src/i18n.rs`, translate, and add the language to `docs/<lang>/`. Weblate can open PRs automatically.
